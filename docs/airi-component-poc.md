# AIRI component experiment: automatic cancellation is blocked

**Do not adopt the browser automatic-cancel adapter.** Independent real-host fault injection of the shared generation-only adapter pattern (using the XState candidate) held an old actor callback, completed its old Native turn, started a newer turn in the same generation, then released the old callback. The generation-only cancel binding interrupted the newer turn. This is an R04/R06 failure for autonomous actors, not a flaw in the human stop-current UI. A future actor port must capture the exact canonical Native turn and use a Node owner guard. The historical positive probes below do not override this failure.

## Executed probes

- `probe.mjs` (original scratch probe): actual upstream orchestrator with explicitly synthetic LLM port. Two-turn user history plus scene context, exact-turn abort, wrong-turn no-op, noncooperative provider replacement, late-output rejection, session A/B isolation.
- `native-probe.mjs` (original scratch probe): actual upstream orchestrator using existing Fisch `openCodexTransport.submitUser/interruptUser`, connected over authenticated loopback WebSocket to a separate scripted app-server child (`native-fixture.mjs`). No official Native binary or credentials. It passes actual correlated ACK, delta and completion through the port, interrupts an exact acknowledged turn, waits for canonical completion/interrupt ACK, and rejects a delayed old Native delta. The scripted child retains separate A/B histories, including concurrent B while A remains held. Six actual starts include one real10s post-write timeout, five canonical completions, one exact interrupt, and a blocked subsequent resend. One upstream runtime is captured per owner/session to prevent a UI active-session change from redirecting composition. This is a protocol component POC, not the complete production broker/controller integration.
- `bounds-probe.mjs` (original scratch probe): actual upstream registry behind `bounded-context.mjs`. Per-user/session/epoch identity, 4 writers, 4 entries/writer, 1024 bytes/text, 8192-byte serialized active context, 12 history records. Rejects 1000 append floods. `removeWriter` is explicitly NOT a privacy wipe; reset wipes active/history and invalidates old ownership. Caller owner identity is cloned/frozen and wrong user, session and epoch are rejected. No upstream claim of bounded active memory: upstream append-self itself is unbounded.

## Integration contract and unresolved gates

Production reuse must use the existing LiveConversation/Native canonical ownership and broker FIFO, never create a second agent, use AIRI stock provider adapters, replay prompts into another model, or grant new tools. AIRI cancel signal is an interruption request; only exact Native turn ACK/completion establishes actuator outcome. Unknown post-write outcomes remain sticky and are never automatically retried. The prototype deliberately forwards only the latest explicit user text to Native, not AIRI-composed history/runtime-context. Therefore its context assertions establish upstream composition only, not end-to-end delivery of scene context to Native. Native callbacks require matching owner/session/epoch and current turn; the prototype is intentionally not a replacement for that controller.

The corrected AIRI canonical-binding browser probe passed against real Fisch MCP/gateway/compiler/renderer. Its single epoch/sequence trace contains received, admitted, applied, frame_submitted, frame_changed_proxy and completed, and the body reports scene wall. Creative remix/undo R09 remains NOT RUN. Real model coherence, semantic quality, human enjoyment, microphone/camera/voice, native GPU and full-platform performance are untested.

Gate mapping: R01 pass(component execution/provenance); R02 pass(canonical real host binding exercised, explicitly scripted Native substitute; no real agent/model claim); R03 partial(AIRI composed user/context carryover and A/B isolation only; Native receives latest explicit user text and retains its own history; AIRI scene-context bridge and actual tool outcome NOT RUN); R04 FAIL(browser generation-only automatic cancel can interrupt a newer owner; upstream local late-output protection does not fix ownership); R05 partial(Native completion/interrupt ACK, no Fisch admitted actuator); R06 FAIL(same-generation newer-owner cancellation; per-user context isolation still passes separately); R07 partial(sent timeout sets sticky unknown and blocks next send, explicit fresh-session recovery not yet); R08 pass(actual canonical binding → scripted Native tool selection → real MCP/gateway/compiler/render with matching UUID epoch+seq); R09 not_run; R10 partial(static import audit/runtime loopback fixture only, comprehensive syscall monitoring not run); R11 partial(package metadata/licenses and no assets); R12 partial(resources below). Critical missing gates are not averaged into a global pass.

## Canonical browser adapter attempt history

`browser-probe.mjs` runs AIRI through the real `window.fischLiveConversation` binding, existing production host/controller/broker, and scripted Native fixture. It does not create custom Native ownership maps. First attempt exposed a POC adapter race: an old `canSend=true` DTO after send ACK falsely completed the upstream send; require a revision advance before certifying completion. After that fix the two-send/cancel leg proceeded, but the MCP fixture rejected timestamp-prefixed composed text. Forwarding composed AIRI text changes explicit user intent; adapter now selects the original user-approved text by `options.requestCorrelation.turnId`. Composed turn IDs differ and are unsuitable correlation keys. These are adapter defects found during testing, not production host failures. ## Recommendation

The narrow upstream orchestrator can run behind the existing canonical Native binding and drive an existing Fisch capability. It is an experimental source-component candidate, **blocked for automatic cancellation adoption**: it adds its own queue/history and timestamp composition, so production must retain Native authority, correlate the original explicit intent by requestCorrelation.turnId, wait for a new canonical DTO revision before completion, isolate one runtime per owner, enforce context bounds and redact errors. Do not adopt the entire voice/provider/platform stack for this expression-only goal. Remaining R03/R04/R05/R06/R07/R09/R10/R12 limitations are explicit above; no critical gap is averaged away. Preserve as a separate evidence/probe branch before any production flip.
