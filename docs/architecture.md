# Architecture

The core is independent of Tauri, DOM, Workers and Three.js. The composition root connects a provider adapter, bounded compiler host, scheduler and renderer sink. `npm run check:architecture` enforces the core boundary.

- `contracts`: versioned wire schema and capability manifest.
- `core/ast`: discriminated data types, no executable model code.
- `core/compiler`: strict validation, immutable session macro revisions, bounded expansion, temporal write conflict checks, IR lowering and 64-entry cache.
- `core/runtime`: a single body track, replace/append policy, epoch and sequence checks, monotonic timeline, property baseline release and deterministic shape weights.
- `adapters`: JSONL byte framing, scripted provider, Tauri transport and Three.js renderer.
- `workers`: compiler host, render host and actual OffscreenCanvas/WebGL probe.
- `app`: ownership, lifecycle, mailbox limits, recovery and UI intent wiring.

The compiler mailbox has four in-flight jobs. The render mailbox has four acknowledged messages. Renderer queues have eight pending programs; overload is rejected and counted. Rust uses separate 64-message content and four-message expression permits, with frontend acknowledgement. Content may backpressure its own provider but never waits for the expression compiler or renderer. Cancellation has a direct command/message path; every consumer checks epoch again.

Legacy morphs interpolate seven procedural shape weight vectors over stable seeded particle IDs. Assemblies use deterministic spatial assignment, preserving compatible particle-to-part mappings and transitioning from displayed positions. Replacement captures the current weights, preserving continuity. Geometry buffers are allocated once; lowering is outside the frame loop. Color interpolation is linear-light sRGB conversion. Quality selection retains the first stable particle IDs.

The reference runtime records numeric counters and error codes by default. The optional pane planner sends bounded, credential-redacted actual interaction text to the selected provider; raw messages are held in memory and are not saved by Fisch. Provider data policies still apply. Pane status includes reaction metadata, rendering, ambient motion and idle-scene state rather than raw prompt text. Replay capture requires a checkbox and retains at most 1,000 normalized records in memory. Export is a deliberate local download.

The panel mode (fisch run) is the Node terminal runtime attached to an existing Herdr agent pane. Browser Live (fisch live) has a normal-terminal default with optional Herdr discovery. The panel private IPC and shared compiler/scheduler do not require the Rust gateway. Browser Live and Tauri custom-host mode use the loopback Rust gateway. HTTP POST and MCP share the same frontend Worker compiler and scheduler; the expression core makes no model API call. The terminal agent talks to its provider outside that core. Gateway admission initially waits at most 500ms for compile/scheduler ACK, never for animation completion; unresolved admission returns `pending` and remains tracked until a definitive decision or session closure. See [admission semantics](admission.md). The frontend applies a 450ms admission deadline before forwarding IR. SSE reports separate lifecycle feedback through a 64-event bounded broadcast; four consumers maximum. Control messages use one acknowledged slot and one coalesced latest epoch, independent of expression capacity. Request dedup retains at most 256 receipts for 60 seconds.

The browser capability demo is scripted choreography. The pane planner implements native Codex/Claude inference and an optional Responses structured-output API backend outside the core. It responds to actual interaction hooks, with at most two attempts per user turn; idle never starts inference. Native Codex planning has recorded evidence, while interactive Claude-in-Herdr delivery and human perception remain unverified. Fake HTTP/MCP tests do not establish full M2 acceptance.

`core/geometry` samples free-form assemblies with stable part IDs, per-part motion and target-aware boids. `core/runtime/presence` composes local root motion and validated model-authored part performances without repeatedly submitting ASTs. `integrations/idle-scenes.mjs` plays up to three prepared geometry scenes during idle/done, restores interaction geometry on resumed activity and stores scenes only in memory. `integrations/braille-renderer.mjs` maintains adaptive density/exposure/color history per output session; inline RGB and browser WebGL remain separate render paths.

Known limits: template validation uses context-sensitive representative values, with full validation again on expansion; complex parameterized nested calls need broader testing. State patches are merged into scheduler baselines, but saturated pre-compilation state jobs are explicitly dropped rather than coalesced. Renderer worker recovery falls back once to a main-thread renderer and currently restarts from baseline; context-loss GPU recovery relies on Three.js and stops rendering after the bounded restore budget. These are POC limitations, not completed SRS guarantees.

## Fisch Live mode

`fisch live` adds a browser-local observation/reflex path and direct Codex MCP control. MediaPipe inference runs in a bounded latest-frame worker; only typed observations/events leave the browser. Document and worker CSP headers restrict connections to loopback, including SDK logging. Unexpected GPU camera-track termination has one explicit CPU recovery; manual stop cancels recovery. LiveCompiler stages the bounded extension configuration before the shared AST compiler, and a channel compositor applies reflex/bind/orient/explicit-pose transforms through shared geometry. Live simulates/draws 2,000 particles, while legacy schedulers preserve their existing default. The Live page uses the shared ThreeRenderer on the main thread; the legacy reference still uses its worker/fallback hosts.

The Rust browser gateway adds an origin/host-checked WebSocket with first-message token auth, one observation connection, bounded snapshot/events and one synthetic look request. HTTP/MCP keep their existing admission semantics. Observe reads are independent of the mutation queue; context reads do not consume model events. Real camera images cannot be delivered by this authorized build.

The terminal host connects the existing Codex UI through an authenticated, single-client loopback relay to official app-server stdio. Pairing and relay credentials stay in inherited environment, never command arguments or URLs. Thread instructions are appended; no global provider settings are changed. Only assistant-message deltas drive output activity; tool output never implies replying. The optional Herdr adapter still creates a dedicated pane with transient MCP environment and source-project cwd; an already-running CLI is not assumed to hot-load it. Live serves a freshly built static bundle locally to avoid HMR resetting the camera during coding. The original session remains. Existing trusted native hooks can forward event type through private pane IPC; prompt-context injection is not natively accepted yet, so observe-first is the fallback. No secondary expression planner or old idle-scene director runs in Live. Detailed ownership, budgets, privacy and limits are in [the Live guide](fisch-live.md).

Live initializes a declared particle face using the same bounded assembly compiler. Role metadata applies only to that exact geometry, not arbitrary names. Data-defined lifecycle face controls remain local; semantic poses/illustrations stay agent-authored. Expired semantic channels fade ownership back to lower layers. UI cancel quarantines old epochs and revokes authority; Live MCP never silently replays a gesture across session loss. A bounded trace distinguishes admission, scheduler application and frame/hash proxies without user text or images. Synthetic observation mode is opt-in and labeled. See [Cloud execution/remaining gates](live-cloud-run.md).

The standalone fisch-gateway binary shares gateway code/tests with the Tauri app, compiling with --no-default-features. Desktop remains the default Cargo feature, with its existing prerequisites. This separates browser Live from desktop UI packages without weakening transport authentication, budgets or origin policy.
